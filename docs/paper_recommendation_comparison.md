# 论文建议对照表：私聊对象档案记忆 V2

> 说明：本文档用于对照参考论文《深度人机互动与轻量级状态管理：基于大语言模型的百轮情感演进与无数据库JSON意图识别架构报告》中的建议，记录当前本地实现已经做到哪里、还缺哪些、哪些暂不做。
>
> 对照基准版本：2026-04-13

## 对照表

| 类别 | 论文建议 | 当前实现 | 说明 |
|---|---|---|---|
| 已实现 | 纯本地 JSON 文件系统承载记忆 | 已实现 | 已落地 `memory_v2/{wxid}/private/{entity_hash}/` 目录，使用 `state.json`、`chat_history.jsonl`、`rolling_summary.json` 分层存储。 |
| 已实现 | 意图提取前置层 | 已实现 | 私聊文本先走意图抽取，再决定是否更新档案，再生成回复。 |

| 已实现 | 滚动摘要（Rolling Summary） | 已实现 | 历史达到预算后自动压缩为 `rolling_summary.json`，再与最近对话共同进入回复上下文。 |
| 已实现 | 阶段化情感演进（1-15 / 16-40 / 41-80 / 81+） | 已实现 | `relationship.stage` 由程序按轮次计算，不交给模型自由改写。 |

| 已实现 | 原有人格 Prompt 继续作为回复层使用 | 已实现 | 你现有的优化后提示词仍在后台使用，只是不再承担记忆更新职责。 |

| 部分实现 | 多代理循环（Multi-Agent Loop） | 部分实现 | 已拆成多阶段编排，但仍是单个记忆引擎内的顺序流水线，还不是完全独立的多代理体系。 |
| 部分实现 | 结构化输出的 API 级强约束 | 部分实现 | 目前主要依赖 Prompt + 解析校验 + 回退，没有再叠加 Structured Outputs / Pydantic / Zod 级别强约束。 |
| 部分实现 | 更完整的关系语义建模 | 部分实现 | 已有 `facts / likes / dislikes / traits / communication_style / emotional_triggers / open_loops`，但还没扩成论文里的全量情感建模。 |
| 未实现 | `reasoning_trace` / Chain of Thought 输出 | 未实现 | 这部分是刻意不做的，避免泄露内部思考过程，也减少格式污染风险。 |
| 未实现 | TOON 等更激进的压缩格式 | 未实现 | 当前仍以 JSON / JSONL / JSON Patch 为主，优先易维护和兼容性。 |
| 未实现 | 语音单独模型路由 | 未实现 | 目前代码里已有 `msg.to_text()` 的语音转文字路径，但尚未新增可配置的语音识别模型设置。 |

| 未实现 | 冲突恢复指数等更细粒度心理量化指标 | 未实现 | 目前没有按论文扩成独立的冲突修复/恢复指数体系。 |
| 未实现 | 主动脆弱性自揭示的完整策略层 | 未实现 | 这类更强的人设策略仍停留在 Prompt 风格层，没有做成单独状态逻辑。 |

## 结论

当前实现已经覆盖了论文最核心、最有工程价值的一段：

- 纯本地 JSON 状态机
- 意图抽取前置层
- Patch 增量更新
- 滚动摘要
- 阶段化关系推进
- 抗顺从回复策略

没有完全落地的主要是两类：

1. 更强的模型级输出约束和多代理体系
2. 更细的情感心理指标、语音路由和高级压缩格式

## 后续建议

如果下一轮继续对齐论文，优先级建议是：

1. 语音转写模型路由
2. Structured Outputs 级别的格式强约束
3. 更细的情感呼唤识别与冲突恢复指标
4. 群聊对象记忆扩展
5. 更完整的阶段化人设策略
